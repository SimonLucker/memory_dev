# Memmory data v3

Relational rows, one adapter, pure selectors. ARCHITECTURE.md section 4 is the decision record; this page is the working reference.

## Tables (`supabase/migrations/0001_v3.sql`)

Rows in JS are shaped exactly like the columns, so nothing is mapped.

| Table | Columns |
|---|---|
| `people` | `id, name, first_name, avatar_url, is_user, space_id, created_at`. Users (p1..p5) keep their id; a contact is keyed by its space: `p1_p04` (contact ids collide across spaces). |
| `memories` | `id, owner_id, title, place, starts_at, ends_at, about, class, feeling[], music {name, artist}, importance, cover_moment_id, favorite, demo, legacy (untouched v2 fields), created_at, updated_at` |
| `moments` | `id, memory_id, kind photo/video/voice/text/answer, src, poster, duration, transcript, text, generated_by, question_id, captured_at, position, demo, created_at`. Story order is `position`, then `captured_at`. |
| `memory_people` | `memory_id, person_id, role contributor/tagged`. A contributor is a user who adds moments; tagged people were there. In the store this table is `db.links`. |
| `questions` | `id, memory_id, person_id (who is asked), text, asked_at, answered_at` |
| `recaps` | `id, memory_id, beats jsonb, song jsonb, created_at` |
| `app_settings` | `key, value`. Row `auth_required = false` keeps the anon key all-seeing. Flip to `true` once JWTs carry `person_id`; every policy is `app.open() or <ownership>`. |

The migration renames the v2 jsonb tables to `memories_v2` and `cards_v2` (the adapter's legacy calls follow). `threads` and `profiles` are unchanged.

## Adapter (`api.js`)

`loadSpace(pid) -> { people, memories, moments, links, questions, recaps }` (arrays). `upsert(table, rows)` and `remove(table, id)` (id is a string, or `{memory_id, person_id}` for `memory_people`) are fire-and-forget with the retry ladder. Remote: PostgREST (`memories?select=*,moments(*),memory_people(*),questions(*),recaps(*)&or=(owner_id.eq.<pid>,id.in.(<contributed ids>))`). Dev: the `/__db` vite middleware, which merges every persona's bundled space (v2 JSON through `fromV2`, Isabel's seed) under `src/data/db/<table>.json` and filters like the remote query. A delete of a bundled row is a tombstone in the db file.

## Store (`store.js`)

`db = { people: {}, memories: {}, moments: {}, links: [], questions: {}, recaps: {} }` keyed by id. `emptyDb()`, `toDb(space)`, `putRows(db, spaceOrFromV2Result)`, `withRows(db, table, rows)`, `withoutRow(db, table, id)` (a memory takes its moments, links, questions and recaps with it), `dropMoments(db, ids)`. Every change returns a new object.

## Selectors (`select.js`, memoized by db identity)

```
memoriesOf(db, pid)      owned or contributed, real first then demo, newest first within each
countOf(db, pid)
storyOf(db, id)          { memory, blocks, people, shared, question, related }
                         blocks: hero (first photo), pair, photo (lone), video, voice, text, song
                         (after the last media block), related, question (always last)
                         Block = { kind, moments, by, music? | memories? | question? }
homeOf(db, pid, now)     { hero, cards (max 3: year-ago, question, contributed), latest[3] }
sharedOf(db, id)         Person[] with `label`: owner first as 'You', then first-moment order
relatedOf(db, id, n=3)   earlier memories sharing people or place
recapOf(db, id)          Beat[] stored, else composed (5s a beat, a voice stretches the beat
                         after it, a text becomes a quote on the next beat)
                         Beat = { kind, src, poster, duration, by, voice, quote }
songOf(db, id)           the recap's song, else memory.music
momentsOf(db, id)        moments in story order
```

## Bridge (`bridge.js`)

`fromV2(v2, ownerId, now) -> { memory, moments, links, people }`: photos, voice, videos become moments (`<id>_p0`, `<id>_v0`, `<id>_vid0`, deterministic), `who[]` becomes contact rows plus tagged links (a registered persona becomes a contributor link), everything else lands in `memory.legacy`. `toV2(db, id)` is the inverse; arrays and `music` are always present, `class`, `importance`, `favorite` only when set.

## Personas and demo (`personas.js`, `demo/isabel.json`)

`PERSONS` keeps the legacy shape plus `space`; `bundledSpace(pid)` is the db from bundled data only (the showcase never touches the network). Isabel's seed is generated by `node scripts/seed-isabel.mjs` (photos copied to `public/photos/isabel/`). Her six roadmap memories are real, the six fillers are `demo: true`.
